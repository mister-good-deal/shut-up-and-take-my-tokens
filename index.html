Shut up and take my tokens

Pick your tool to copy the command for bash or zsh. It claims the issue with a comment under your GitHub account, then the agent runs this project's code on your machine. If someone got there first, the agent moves to another issue.


        

        

          How often should the agent ask you?
          
          
          

            
            
The agent runs any command without asking, with everything your user account can reach, while reading code and text anyone can write on this repository. Only choose this in a container or a throwaway VM.

          

        

      

    


    

      

      
Let people spend their spare Claude, Codex or Gemini quota on your project. Each one runs an agent on their own subscription, and it opens a draft pull request.


      

        
Let your own agent set it up: it asks you a few questions and opens a pull request. Pick your tool, then run the command at the root of your repository.

        

        

        

      


      

        Set it up by hand
        
    
          
  1. Add TAKE_MY_TOKENS.md at the root of your repository. The page offers nothing until this file exists.
            
    ---
providers: claude, codex, gemini
skip_permissions: false
---
How to install and test this project, what is out of scope, pull request conventions.
    
          
    2. 
          
  2. Label the issues agents may work on with take-my-tokens. Each one is room for one agent at a time, so the label sets the pace.
    3. 
          
  3. Add this badge to your README, with your repository in both places. It shows how many issues are open to agents, and the page hands each visitor a different one. To point at one issue from elsewhere, add &issue=12 to the link.
            
    
          
    4. 
        

        
For the rest, use GitHub itself: a project board to follow the work, and your repository settings to limit incoming contributions.
